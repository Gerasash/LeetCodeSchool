# 🎓 SchoolLeetCode — Образовательная платформа для изучения C++ с ИИ-наставником

**SchoolLeetCode** — это интерактивная веб-платформа для обучения программированию на C++, спроектированная специально под реалии школьного курса информатики (7–11 классы) и базовых курсов университетов (1–2 курсы). 

В отличие от «взрослых» платформ спортивного программирования (LeetCode, Codeforces, Яндекс Контест), платформа ориентирована не на соревновательный отбор, а на **педагогический процесс**: развитие алгоритмического мышления без выгорания, поддержка ученика в момент ошибки и автоматизация рутины учителя.

---

## 📌 Зачем нужен проект (Проблематика и ценность)

### Боли учеников и студентов
1. **Стена непонимания:** Ошибки компилятора C++ (`g++`) пугают начинающих десятками строк непонятного лога, а падение на скрытых тестах в классических системах оставляет ученика в тупике («Неверный ответ на тесте #4» — и никакой подсказки, почему).
2. **Искушение списать:** Традиционные чат-боты (ChatGPT, Claude) при первом же вопросе выдают готовый листинг кода. Ученик вставляет его, не вникая в логику, что полностью убивает обучение.

### Боли преподавателей
1. **Колоссальная рутина:** Проверка десятков однотипных лабораторных и домашних работ вручную отнимает часы времени.
2. **Сложность диагностики класса:** Трудно понять, где именно класс застрял — в синтаксисе циклов, логике условий, неинициализированных переменных или выходе за границы массива.

### Решение SchoolLeetCode
- **Встроенная теория и контекст:** Краткий теоретический конспект темы доступен прямо рядом с условием задачи.
- **Сократовский ИИ-наставник:** ИИ не пишет код за ученика, а подсвечивает проблемную строку в редакторе и задаёт наводящие вопросы по 3-уровневой лестнице подсказок.
- **Кабинет преподавателя:** Создание учебных групп, выдача ДЗ в один клик, матрица успеваемости класса и **ИИ-сводка типичных ошибок**, формулирующая рекомендации: что именно разобрать на следующем уроке.

## 🛠️ Стек технологий

Проект построен на современном, легковесном и производительном стеке без избыточных абстракций:

### Frontend
- **Ядро:** React 19 + TypeScript + Vite.
- **Стилизация:** Tailwind CSS v4 (современная тёмная тема, адаптивный двухколоночный интерфейс).
- **Редактор кода:** `@monaco-editor/react` (движок VS Code) с подсветкой синтаксиса C++, номерами строк и динамическими декорациями (decorations API) для подсветки ошибочных участков кода.

### Backend
- **Ядро:** Python 3.11+ + FastAPI (высокая скорость, валидация данных, автодокументация OpenAPI/Swagger).
- **Валидация:** Pydantic v2 с автоматической генерацией `camelCase` для клиентского API (`alias_generator=to_camel`) и `snake_case` внутри Python.
- **База данных:** SQLite + SQLAlchemy 2.0 (строго асинхронный движок через `aiosqlite`). Спроектировано с возможностью мгновенного переключения на PostgreSQL.
- **Миграции БД:** Alembic (с поддержкой `render_as_batch=True` для безопасной модификации таблиц SQLite).
- **HTTP-клиент:** `httpx` для асинхронных запросов к песочнице Piston.

### Песочница выполнения C++
- **Docker + Piston:** Изолированная среда выполнения кода (`ghcr.io/engineer-man/piston`). Код учеников **никогда не запускается на хосте** — компиляция и выполнение изолированы в контейнере с ограничениями по времени и памяти.

### ИИ-модуль
- **DeepSeek API (`deepseek-chat`):** Подключение через официальный SDK `openai` в строгом JSON-режиме (`response_format={"type": "json_object"}`).

## 🤖 Как работает нейросеть DeepSeek (по API)

В платформе DeepSeek выполняет две ключевые педагогические роли:

### 1. Персональный ИИ-наставник ученика (Сократовский метод)
Когда ученик отправляет решение и получает ошибку (`compile_error`, `wrong_answer`, `runtime_error`), бэкенд может сформировать запрос к DeepSeek:
1. **Нумерация строк:** Бэкенд построчно нумерует код (`1 | ...`), чтобы нейросеть точно идентифицировала строки ошибки.
2. **Защита скрытых тестов:** Если упал скрытый тест, бэкенд передаёт его входные и выходные данные в LLM для анализа, но системный промпт строго запрещает называть ученику конкретные числа скрытого теста.
3. **3 уровня подсказок:**
   - **Уровень 1 (Общий ориентир):** Указание строк (`lineStart`, `lineEnd`), тип ошибки (`syntax`, `logic`, `edge_case`, `runtime`) и наводящий вопрос.
   - **Уровень 2 (Детализация):** Указание на конкретную логическую нестыковку (например, поведение отрицательных чисел при делении с остатком в C++).
   - **Уровень 3 (Разбор концепции):** Объяснение правила языка без готового кода задачи.
4. **Кэширование:** Ответ кэшируется в памяти по хешу кода, исключая повторные платные запросы к API.

### 2. ИИ-аналитика типичных ошибок класса для преподавателя
Учитель может запросить сводку по группе за один клик:
1. **Анонимизация данных:** Реальные ФИО учеников маскируются (`Ученик #1`, `Ученик #2`). Персональные данные в LLM не передаются.
2. **Агрегация попыток:** Бэкенд выбирает до 25 последних неуспешных посылок учеников по заданиям группы (фрагменты кода и текст ошибок).
3. **Результат для учителя:**
   - Общее педагогическое резюме (`overallSummary`).
   - Структурированный список частых ошибок (`commonMistakes`) с указанием процента затронутых учеников.
   - Методические рекомендации («Что разобрать на следующем уроке»).

## 📐 Как была организована разработка продукта

Проект создавался в тесной связке **Человек (Product Manager / QA) + ИИ-ассистент (Lead Fullstack Developer)** по методологии **вертикальных срезов (Vertical Slice Architecture)**:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. docs/PRD.md ──► 2. docs/ARCHITECTURE.md ──► 3. docs/TASKS.md │
└──────────────────────────────┬──────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
      Срез 1: Скелет C++                    Срез 2: DeepSeek API
  (Monaco + FastAPI + Piston)          (3 уровня подсказок + подсветка)
            │                                     │
            ▼                                     ▼
      Срез 3: База данных SQLite            Срез 4: Кабинет преподавателя
 (Треки, темы, задачи, теория, прогресс)   (Группы, ДЗ, матрица, ИИ-сводка)
```

1. **Единый источник правды (`docs/`):**
   - `docs/PRD.md` — концепция, целевая аудитория и сценарии использования.
   - `docs/ARCHITECTURE.md` — контракты API (всегда в `camelCase`), схема базы данных и пайплайн компиляции.
   - `docs/TASKS.md` — детальный трекер выполненных и запланированных задач.
2. **Инкрементальная поставка ценности:**
   - **Срез 1:** Проверка C++ кода в песочнице Piston, редактор Monaco, первая задача.
   - **Срез 2:** Подключение DeepSeek API, наводящие подсказки и визуальная подсветка строк в редакторе.
   - **Срез 3:** База данных SQLite, асинхронный SQLAlchemy, иерархия курсов «Школа / ВУЗ → Трек → Тема → Задачи», вкладка теории темы, скрытые тесты.
   - **Срез 4:** Кабинет преподавателя, выдача домашних заданий по инвайт-кодам, матрица прогресса и ИИ-анализ типичных ошибок группы.
3. **Непрерывный контроль качества:**
   - Ни одна задача не принималась без прохождения полного цикла проверок:
     `python -m compileall`, строгий линтинг `ruff`, компиляция TypeScript `tsc -b && vite build` и `oxlint`.

## 🚀 Как запустить и продемонстрировать проект преподавателю

Для демонстрации проекта преподавателю есть два основных пути. Ниже подробно описаны оба варианта.

---

### Вариант 1 (Рекомендуемый): Локальный запуск на компьютере

Это **наиболее надёжный и быстрый способ** для демонстрации или защиты диплома/курсовой:
- Изолированная песочница Piston работает локально без задержек сети.
- Полная независимость от таймаутов и ограничений бесплатных облачных тарифов.

#### ⚠️ Важное предупреждение о безопасности `.env` и Git
> **НИКОГДА не выкладывайте `.env` файл в ПУБЛИЧНЫЙ репозиторий GitHub!**  
> Автоматические сканеры GitHub отслеживают ключи в публичных коммитах за доли секунды. Ваш ключ DeepSeek будет мгновенно заблокирован провайдером из соображений безопасности.
>
> **Как поступить безопасно:**
> 1. Либо сделайте репозиторий **Private (приватным)** на GitHub и добавьте преподавателя в Collaborators. В этом случае добавить `.env` в репозиторий безопасно.
> 2. Либо отправьте преподавателю ссылку на публичный GitHub (где `.env` скрыт через `.gitignore`), а сам файл `.env` с рабочим ключом приложите в архиве или передайте в личных сообщениях.

#### Пошаговая инструкция запуска для преподавателя

**1. Предварительные требования:**
- Установленный [Docker Desktop](https://www.docker.com/products/docker-desktop/) (должен быть запущен).
- [Python 3.11+](https://www.python.org/downloads/)
- [Node.js 18+](https://nodejs.org/)

**2. Настройка переменных окружения:**
В корне проекта должен лежать файл `.env` (можно скопировать из `.env.example`):
```env
PISTON_URL=http://localhost:2000
DEEPSEEK_API_KEY=sk-ваш-ключ-deepseek
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DATABASE_URL=sqlite+aiosqlite:///./school_leetcode.db
TEACHER_ACCESS_KEY=teacher123
```

**3. Запуск песочницы Piston (в корне проекта):**
```bash
docker compose up -d
python scripts/setup_piston.py
```
*(Скрипт убедится, что Piston активен, и автоматически установит компилятор GCC/C++).*

**4. Запуск бэкенда (FastAPI):**
```bash
cd backend
python -m venv venv
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Linux / macOS:
# source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
*База данных `school_leetcode.db` создастся и наполнится демо-курсами, задачами и демо-группой автоматически при первом старте.*

**5. Запуск фронтенда (React):**
В отдельном терминале:
```bash
cd frontend
npm install
npm run dev
```

**6. Откройте в браузере:** `http://localhost:5173`

### Вариант 2: Публичный деплой в облако (для онлайн-доступа)

Если требуется дать преподавателю прямую ссылку в интернете без установки программ на его компьютер:

#### Архитектура облачного деплоя
1. **Frontend (Бесплатно на Vercel или Netlify):**
   - Репозиторий подключается к Vercel.
   - Root directory: `frontend`.
   - Build command: `npm run build`.
   - Output directory: `dist`.
   - В коде фронтенда в `src/api.ts` параметр `API_BASE` заменяется на URL задеплоенного бэкенда.
2. **Backend и База данных (Render / Railway):**
   - Python-приложение FastAPI можно задеплоить на бесплатный тариф Render.com или Railway.app.
   - Переменные окружения (`DEEPSEEK_API_KEY`, `TEACHER_ACCESS_KEY` и др.) прописываются в панели управления хостинга (Environment Variables).
3. **Песочница Piston в облаке:**
   - Бесплатные serverless-платформы (Vercel/Render) **не позволяют запускать Docker внутри Docker**, поэтому поднять локальный контейнер Piston на них нельзя.
   - **Решение без затрат:** переключить `PISTON_URL` в `.env` бэкенда на официальный публичный сервер Piston API:
     ```env
     PISTON_URL=https://emkc.org/api/v2/piston
     ```
     Публичный API Piston бесплатен, содержит уже предустановленный C++ (GCC) и не требует развёртывания своего Docker-контейнера!
   - **Решение с полным контролем:** арендовать дешёвый VPS (например, Timeweb Cloud, Aeza или FirstVDS за ~200–300 руб/мес) с Ubuntu, установить Docker и поднять весь проект через `docker compose`.

## 📋 Сценарий демонстрации платформы

Для быстрой и эффектной демонстрации возможностей преподавателю используйте следующий сценарий:

### Сценарий ученика
1. **Каталог задач:** Нажмите **«📚 Каталог и задания»** в левом верхнем углу. Покажите разделение на «Школа (9 класс)» и «ВУЗ (1 курс)», а также вкладку **«Теория»** в карточке задачи.
2. **Проверка C++ кода:** Нажмите **«▶ Проверить решение»** — покажите моментальный прогон по тестам в песочнице и отображение скрытых тестов (`🔒 Скрытый тест #3 не пройден`).
3. **ИИ-наставник:** Допустите логическую ошибку (например, `i <= n` вместо `i < n` или сложение без условия чётности). ИИ DeepSeek подсветит проблемные строки в Monaco Editor и даст сократовскую подсказку. Нажмите **«Подсказать точнее»**, чтобы показать постепенную эскалацию подсказок (Уровни 1 → 2 → 3).
4. **Домашние задания:** Перейдите во вкладку **«📋 Мои задания»**, введите своё имя и инвайт-код `DEMO9A`. Откроется ДЗ «Массивы», выданное учителем.

### Сценарий преподавателя
1. В шапке сайта нажмите **«👨‍🏫 Кабинет преподавателя»**.
2. Введите ключ доступа: `teacher123`.
3. **Матрица успеваемости:** Выберите группу **«9А — Демо-группа»** → вкладка **«📊 Успеваемость»**. Покажите интерактивную сводную таблицу по всем ученикам и задачам с историей попыток.
4. **Выдача ДЗ:** Во вкладке **«📝 Задания (ДЗ)»** создайте новое задание, выбрав нужные задачи чекбоксами из каталога.
5. **ИИ-аналитика ошибок:** Откройте вкладку **«🤖 ИИ-аналитика ошибок»** и нажмите **«✨ Сгенерировать ИИ-сводку»**. DeepSeek проанализирует неуспешные попытки демо-учеников и выведет готовый конспект для учителя: какие ошибки допустил класс и что именно разобрать на следующем уроке.
